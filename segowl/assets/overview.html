SegOWL · segmentation testing for pentesters and auditors

Rigour in the scans. Visibility on the flows. Quality in the report.

You know nmap. SegOWL turns the scans you run from inside the perimeter into the two views a segmentation review needs, per Zone and per Source, set against what the client says should pass.

The work process

  1. Define the inventory
    One line per Interface: IP and Zone (the segmentation intent: T0, users, DMZ, OOB…), then type and Machine name, both optional: names can later be filled from the Scans' DNS resolution. From the client's spreadsheet or the client's zip. Inventory & Zones
  2. Select your Auditor Kit
    Apply your kit (Scan Profiles, Port Groups, Port Labels): every Source runs the same method. Auditor Kit › Kits
  3. Configure optional
    Tune a profile for this client: ports found by product or tag, options, the command shown live. Save it as a new version to keep it in your kit. Scans
  4. Run on the Sources
    One script per Source, targets = the whole inventory minus the Source's Machine. Drop the .xml / .gnmap / .nmap on the Source's row: the views regenerate. Scans
  5. Define the Flow Policy optional
    Allow or deny, Zone by Zone, starting from the flows you observed. Only an explicit deny makes a Finding; the rest stays undeclared, listed apart. Flow Policy
  6. Matrices & diagrams
    Zone and Source views, Findings, retests compared. Select a client or a target set and drop them into your pentest or audit report, or hand over the offline HTML report. Report
